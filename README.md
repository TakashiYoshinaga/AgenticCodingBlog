# 🌍 太陽系デモ — Three.js / WebXR

ビルドツールを一切使わない、HTML + CSS + 素の JavaScript だけで動く太陽系デモです。
Meta Quest のブラウザから開くと、AR モードで実空間に太陽系を出して眺められます。

- npm / bundler 不要。ローカルサーバーに置くだけで動く
- 外部画像テクスチャゼロ。惑星の模様・土星の環・星・ラベルはすべて `CanvasTexture` で生成
- 日本語 / 英語の切り替えに対応（UI・案内文・惑星名すべて）
- Three.js 学習用に、役割ごとにファイルを分割

---

## 実行方法

リポジトリのルートで簡易サーバーを立てて開くだけです。

```bash
python3 -m http.server 8000
```

ブラウザで <http://localhost:8000> を開きます。

> `file://` で直接開くと ES モジュールが CORS で読めません。必ずローカルサーバー経由で開いてください。

Node があるなら次でも構いません。

```bash
npx serve -l 8000
```

## 操作方法

### PC / スマホ

| 操作 | 動作 |
| --- | --- |
| マウスドラッグ | 視点を回転 |
| ホイール / ピンチ | ズーム |
| `W` `A` `S` `D` | カメラ移動 |
| `Q` / `E` | 下降 / 上昇 |
| `Shift` | 移動を加速 |
| `Space` | 一時停止 |
| `L` / `O` | ラベル / 軌道線の表示切替 |
| `+` / `−` | 再生速度（0.25x 〜 100x） |
| `R` | 視点をリセット |

画面下の **`EN` / `日本語` ボタン**で表示言語を切り替えられます（UI・WebXR の案内文・惑星名すべて）。
初回はブラウザの言語設定から自動で決まり、以降は `localStorage` に保存されます。

### Meta Quest（AR / VR）

「ARで見る」ボタンでセッションを開始します。太陽がユーザーの約 1m 前方、
通常表示よりずっと小さい卓上サイズ（初期スケール 2%、全体で直径 2m ほど）で出ます。

| 操作 | 動作 |
| --- | --- |
| 右スティック ↑↓ | 太陽系のスケール変更（太陽を中心に拡大縮小） |
| 左スティック ←→ | 視点回転 |
| 左スティック ↑↓ | 太陽系を手前 / 奥へ移動 |
| トリガーを押している間 | 掴んで移動（位置のみ追従し、コントローラの角度は反映しない） |

WebXR が使えない環境ではボタンが無効化され、画面下に日本語の案内文が出ます。
エラーで止まることはなく、通常表示としてそのまま動きます。

## Quest から接続する方法

WebXR は **secure context（HTTPS または localhost）でしか動きません**。
PC で立てたサーバーに `http://192.168.x.x:8000` のような IP 直打ちでアクセスすると、
ページは表示されても AR は開始できません（その旨の案内文が出ます）。

対処は次のいずれかです。

1. **GitHub Pages などの HTTPS に置く** — いちばん簡単
2. **`adb reverse` でポートを転送する** — Quest を開発者モードにして USB 接続し、
   ```bash
   adb reverse tcp:8000 tcp:8000
   ```
   Quest のブラウザで <http://localhost:8000> を開く（localhost なので secure context 扱い）
3. **自己署名証明書で HTTPS サーバーを立てる**

## 実装上のポイント

### 公転周期は実比、サイズと距離は非実比

惑星の**公転周期は地球を 1 とした実際の比率**をそのまま使っています
（水星 0.2408 / 木星 11.862 / 海王星 164.79 …）。
地球 1 周 = 12 秒なので、海王星は 1 周に約 33 分かかります。
外惑星の動きも見たいときは速度を 25x や 100x に上げてください。

一方、**惑星の半径と軌道半径は実比ではありません**。実比にすると太陽以外が
ほぼ見えなくなるため、内惑星が団子にならず海王星が画面に収まる値に手調整しています。

**月の公転周期だけは実比ではありません。** 実際の 27.32 日をそのまま使うと
1 周 0.9 秒になり目が回るため、約 4 倍に引き伸ばしています。

自転も同じ時間軸に載せると 1 地球日 = 33ms になってしまうので、
実周期の 0.35 乗で割って圧縮しています。速い順（木星 > 地球 > 火星 > 水星 > 金星）と
金星・天王星の逆行の向きは保たれます。

### 太陽に近い惑星が白飛びしない工夫

単一の設定ではなく多層で効かせています。

1. `ACESFilmicToneMapping` — ハイライトを 1.0 でぶつ切りにせずロールオフさせる
2. `outputColorSpace` と全 CanvasTexture の `colorSpace` を揃える（ずれると二重に明るくなる）
3. **`PointLight.decay = 0.3`** — 物理的な 2（逆二乗）だと距離 8 の水星と距離 51 の
   海王星で明るさが約 100 倍違い、水星が確実に飛ぶ。0.3 なら約 2 倍差に収まる
4. `MeshStandardMaterial` の `roughness 0.92` / `metalness 0` — 鋭いスペキュラを出さない
5. 環境光を足して夜側が真っ黒な「穴」にならないようにする
6. 太陽本体は `MeshBasicMaterial`（アンリット）

実測で、水星の昼側のピークは 107/255、いちばん明るい金星でも 183/255 に収まり、
飽和ピクセルはゼロです。

### AR ではスケールに応じて光量を補正する

`decay > 0` の点光源の照度は光源からの距離で決まります。AR で root を 1/50 に縮めると
太陽と惑星の距離も 1/50 になるため、**照度が `pow(0.02, -0.3)` ≒ 3.2 倍に跳ね上がります**。
その結果、

- AR だけ昼側が飽和寸前になり、夜側との差が激しくなる（実機で「コントラストがどぎつい」状態）
- 右スティックで拡大縮小するたびに明るさが変わる

という 2 つの問題が出ます。`applyLighting()` が `intensity x pow(scale, decay)` を掛けて
これを打ち消すので、**どの縮尺でも明るさは一定**です。

あわせて、AR ではパススルー映像が明るく夜側が「黒い穴」に見えるため、
環境光を 2.5 → 5.2 に持ち上げています（`AMBIENT_INTENSITY_AR`）。

| | 昼側ピーク | 夜側平均 | コントラスト比 |
| --- | --- | --- | --- |
| 通常表示 | 219 | 27 | 8.1 |
| AR（初期 2% / 拡大 15% / 100% いずれも） | 220 | 53 | 4.2 |

### 軽量化

- ポストプロセス（UnrealBloom など）は不使用。WebXR と相性が悪く重いので、
  太陽の発光は Additive な Sprite 2 枚のハロで代替
- 影（shadowMap）なし
- 球ジオメトリは 3 段階を共有し、大きさは `mesh.scale` で付ける
- 星 4000 点は `Points` 1 ドローコール
- 全体でドローコール 18、三角形 8.4k 程度
- テクスチャ生成は起動時の 1 回だけ。13 万画素 × 10 枚を回すので、
  パレットは 256 段の LUT に焼き、走査中は `[r,g,b]` を new せず使い回している
  （シーン構築全体で実測 295ms / `__solar.buildMs` で確認できる）

### ラベル

`CSS2DRenderer` は WebXR で描画されないため、DOM ではなく **Sprite + CanvasTexture** を
使っています。

ラベルは**惑星と同じワールド固定サイズの 3D オブジェクト**として扱います。
画面比を一定にすると、引いたときに惑星だけが小さくなってラベルが相対的に肥大し、
AR で縮小しても文字だけ元の大きさのまま残ってしまうためです。
ワールド固定なら、ラベルは `bodyGroup`（= root の子）なので **AR で root を縮めれば一緒に縮みます**。

大きさは `LABEL_BASE_HEIGHT x pow(半径, 0.35)`。完全比例にしないのは、
水星や月の名前が読めなくなるからです（太陽 3.90 / 木星 3.35 / 地球 2.40 / 月 1.52）。

両端だけ `updateLabels()` が面倒を見ます。

| 定数 | 値 | 役割 |
| --- | --- | --- |
| `LABEL_BASE_HEIGHT` | 2.4 | 地球（半径 1.0）のラベルのワールド高さ |
| `LABEL_MAX_ANGULAR` | 2.24° | 寄ったときに画面を埋めないための上限 |
| `LABEL_FADE_START` / `_END` | 0.9° / 0.45° | 遠くて読めない大きさになったらフェードアウト |

結果、**ラベル / 惑星の見かけ比が距離によらず 1.20 で一定**になります（上限の掛からない範囲）。
初期視点での板の視野角は 1.40°。

> **サイズを変えるときは `LABEL_BASE_HEIGHT` と `LABEL_MAX_ANGULAR` を必ず同じ比率で動かします。**
> 片方だけ変えると、上限に掛かる範囲（寄ったとき・AR）とそれ以外で大きさの比が崩れます。
> `LABEL_MAX_ANGULAR` は AR でのラベルの大きさをほぼ直接決めます（初期スケール 2% で 1m 先を
> 見ると素の値が 3.6° 相当になり、必ず上限に掛かるため）。実機で調整する場合はここを触ります。
>
> フェードの閾値は「読める大きさかどうか」の基準なので、ラベルを小さくすると
> **フェードが始まる距離は近くなります**（現状: 初期視点 98.7 では全ラベルが不透明、距離 200 で 0.55）。

ラベルは**常に手前に描かれます**（`depthTest: false`）。惑星に自分のラベルを隠されないための
意図的な選択で、代償として奥の天体のラベルが手前の天体を突き抜けて見えます。
なお大きさは上記のとおりワールド固定なので、前後関係は「重なり順」だけが例外で、
遠近によるサイズ変化は正しく付きます。

言語切り替え時は `refreshLabels()` が全ラベルのテクスチャを焼き直します。
このとき**旧テクスチャを必ず `dispose()`** しないと、切り替えのたびに GPU メモリが漏れます
（20 回切り替えても `renderer.info.memory.textures` が 25 のまま増えないことを確認済み）。

## デバッグ用

コンソールから `__solar` で中身を触れます。

```js
__solar.world.sunLight.intensity = 10   // 明るさを変える
__solar.sim.speed = 100                 // 再生速度
__solar.world.root.scale.setScalar(0.02) // AR 相当のスケールを再現
```
